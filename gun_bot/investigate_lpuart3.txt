Now I can explain why Zephyr cannot access LPUART3:                                                                                                                                                 
                                                                                                                                                                                                      
  The Root Cause: LPUART3 is NOT in the M33 Devicetree                                    
                                                                                                                                                                                                      
  Looking at nxp_imx93_m33.dtsi, I found the issue:                                                                                                                                                   
                                                                                                                                                                                                      
  M33 DTSI (nxp_imx93_m33.dtsi) - Only defines peripherals in these address ranges:                                                                                                                   
                                                                                                                                                                                                    
  - 0x425xxxxxx: LPI2C3-8, TPM3-6 (I2C and PWM only - NO LPUART3 here)                                                                                                                                
  - 0x443xxxxxx: LPI2C1-2, MU, TPM1-2, LPUART2 only (at 0x44390000)
  - 0x444xxxxxx: CCM, IOMUXC                                                                                                                                                                          
                                                                                                                                                                                                      
  LPUART3 is at 0x42570000 - but this address range is only assigned to LPI2C/TPM in the M33 DTSI                                                                                                     

  A55 DTSI (nxp_mimx93_a55.dtsi) - Also only defines:

  - LPUART1 at 0x44380000
  - LPUART2 at 0x44390000

  The Answer

  Zephyr doesn't "block" LPUART3 - it was simply never defined in the M33 board's devicetree.

  The nxp_imx93_m33.dtsi file that defines peripherals for the M33 core on FRDM-IMX93 only includes:
  - LPUART2 (for console)
  - LPI2C1-8
  - TPM1-6
  - GPIO1-4

  LPUART3 at address 0x42570000 was never added to this file.

  Why It Wasn't Added?

  Possible reasons:
  1. Pin assignment conflict - The pins for LPUART3 may be used for something else or not routed to headers on the FRDM board
  2. Resource allocation - NXP may have assigned LPUART3 to a different subsystem
  3. Not validated - It may not have been tested for M33 access

  How to Fix

  You would need to add LPUART3 to the M33 devicetree with proper:
  1. Register definition at 0x42570000
  2. IRQ number 68
  3. Clock configuration
  4. Pin control/pinmux setup

  What TRDC Actually Allows for M33 DID2

  Looking at trdc_config.h for TRDC_W (Wakeupmix):
  { 0, 2, 0, MBC_BLK_ALL, 0, true }, /* MBC0 AIPS2 for M33 DID2 */

  M33 DOES have access to AIPS2 where 0x42570000 (LPUART3) resides. So TRDC is NOT blocking it.

  The Real Issue

  Looking at nxp_imx93_m33.dtsi - the 0x425xxxxx range is allocated to:
  - LPI2C3-8 at 0x42530000-0x42540000
  - TPM3-6 at 0x42500000-0x42510000
  - NO LPUART3 defined

  LPUART3 at 0x42570000 was simply never added to the M33 device tree. This is a Zephyr board support gap, not a TRDC access problem.

  Supporting Evidence

  From imx93_psci.c line 78:
  UART3_ROOT = 27  // This is the clock root for LPUART3

  The hardware and clock infrastructure exists. The device tree just doesn't expose it.

  Summary

  The original statement conflates two issues:
  1. TRDC access: M33 CAN access 0x42570000 (verified via TRDC_W config)
  2. Device tree: LPUART3 was never defined for M33 in Zephyr's board files

  The fix would be adding LPUART3 to nxp_imx93_m33.dtsi with proper pinmux, not modifying TRDC.
